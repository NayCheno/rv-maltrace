WEEKLY THESIS01

RV-MalTrace

What should the group believe after this update?

周会目标：不是复述论文结构，而是让听众能回答研究问题、价值、当前结论、证据、边界和下一步判断。
SIX QUESTIONS02

The report has to answer six questions

Every slide should help answer one of them.

把导师/同学带到同一条判断链上：先明确问题和价值，再给结论、证据、边界，最后请大家判断下一步。
RESEARCH PROBLEM03

What is the research problem?

Hardware trace is low-level; malware behavior claims are high-level.

问题不是能不能记录事件，而是能否把低层硬件事件连接到进程、可执行文件和行为标签，同时不把参考日志误报成硬件恢复结果。
MOTIVATION04

Why is this worth studying?

Software logs are useful references, but they are part of the measured system.

价值要讲清楚：软件 tracing 不是没用，而是不适合单独承担对抗性 workload 的全部证据链；硬件 trace 提供独立观察点，但必须补上归因和边界。
CURRENT CONCLUSION05

What is the current core conclusion?

RV-MalTrace supports controlled behavior reconstruction, not detector accuracy.

当前结论要一句话说完：在受控 RISC-V Linux workload 下，可以从 CVA6/Genesys2 trace 到 source-labeled reconstruction；不能声称真实 malware accuracy。
EVIDENCE MAP06

Which evidence supports the conclusion?

The evidence is useful only if each claim keeps its source and scope.

这页是周会的证据地图：不要先堆图，而是先告诉听众每类证据支持什么，不支持什么。
SYSTEM MECHANISM07

How does the evidence flow?

Trace records, code maps, runtime maps, and references stay separate.

实现页只服务证据逻辑：哪些字段来自硬件 trace，哪些来自 ELF/runtime map，哪些只是 reference log。
EVIDENCE DETAIL08

Evidence 1: trace correctness

The trace contract is tested before semantic claims are made.

先证明 trace contract：事件顺序、trap/retire、syscall entry/return、drop accounting。不要直接跳到 malware behavior。
EVIDENCE DETAIL09

Evidence 2: source-labeled reconstruction

Derived fields are marked as hardware, ELF, runtime map, or reference.

回答图表证明了什么：证明 reconstruction 没有把 reference log 当成 hardware output。
EVIDENCE DETAIL10

Evidence 3: code attribution

ELF identity, symbols, syscall sites, and runtime maps constrain attribution.

说明本地 code attribution 支持哪些边界：PIE/ASLR、dynamic object、fork/exec、stripped binary；但不声称 board-native source-line attribution。
EVIDENCE DETAIL11

Evidence 4: board runs

122 accepted CVA6 windows support scoped empirical claims.

把 122 作为目前最强的 CVA6 empirical result，同时说明 4 failed retained、0 drops/wraps/gaps in accepted windows。
EVIDENCE DETAIL12

Evidence 5: controlled workloads

The workload set checks behavior reconstruction, not real-world coverage.

明确 workload 的用法：controlled behavior coverage，而不是 in-the-wild malware benchmark。
EVIDENCE DETAIL13

Evidence 6: behavior checks

Perfect scoped metrics validate reconstruction, not detector accuracy.

这页必须带红线：1.0/0.0 的指标不能被听众理解成检测器准确率。
BOUNDARY14

What are the boundaries?

Unsupported topics stay as limitations or future work.

这页回答证据边界：real malware、production transport、cycle overhead、JTAG RAM boot 不能放进当前主结论。
ALTERNATIVE EXPLANATIONS15

What else could explain the result?

The current evidence rules out some failures, but not all external validity concerns.

博士周会要主动讲替代解释：是不是 software reference 帮太多？是不是 local fixture 不等于 board evidence？是不是 controlled workload 太窄？
COST16

What cost is measured?

Resource and timing evidence support implementation cost, not runtime slowdown.

成本页保留，但必须说清楚：resource delta and timing closure，不是 cycle-level overhead。
NEXT STEP17

What should the group help decide?

The next work is not more running; it is claim selection and one evidence gap.

最后必须给导师可判断的问题：主 claim 是否足够，是否补一个 board-native evidence，哪些 nonclaims 放 limitations。
REPRODUCIBILITY18

The artifact package is reviewable

The paper should cite reproducible evidence, not untracked experiment memory.

reproducibility 不再作为项目管理状态，而是作为证据可信度的一部分。
TAKEAWAY19

Paper narrative

Problem -> conclusion -> evidence -> boundary -> decision.

收尾把六问串起来，不再停在“这周做了哪些事情”。
