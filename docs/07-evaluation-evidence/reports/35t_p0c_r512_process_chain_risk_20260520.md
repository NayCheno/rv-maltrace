## Strong vs Weak Boundary

Strong `process_creation_chain` requires all of:

- `clone -> execve -> waitid` in order.
- clone, execve, and waitid target-scoped to the sample code map.
- parent/child boundary evidence: a positive parent-side clone return pid tied to a waitid pid argument.

Weak `process_chain_shape` requires only the strict expected weak shape:

- target-run clone followed by execve followed by wait-like syscall evidence.
- no unrelated weak behavior, including `illegal_instruction_trap`, can satisfy this expected weak shape.

Observed result: weak shape is stable, but strong is blocked because parent/child boundary is not proven. The debug reports show clone parent return candidates such as `18874385` while waitid pid args are `407`, `410`, `419`, `422`, and `431`, with no overlap. This points to return/boundary attribution loss under p0c cap/drop rather than a valid strong process-chain proof.
