FRAMEWORK

先说明系统
到底在做什么

它不是一个“恶意软件检测器”成品，而是一个用硬件记录关键执行事件，再在离线阶段恢复行为证据的研究原型。

Core Question

低扰动记录

目标不是把所有内存访问都录下来，而是在处理器提交路径旁边记录足够解释系统调用行为的事件。

输入

CVA6/RISC-V 的提交、异常、特权级和系统调用相关信号。

输出

可复查的 trace 记录、行为图、样例结果和明确的不能声称项。

原则

trace 满时丢记录并计数，不反压处理器执行。

05 / 34
Trace path

从处理器到行为证据

硬件侧

只采关键事件: 系统调用、返回、异常、上下文、少量参数快照和丢弃计数。

主机侧

把原始记录解码为 JSONL，再与运行时进程信息和对照日志对齐。

汇报结果

报告的是“哪些行为被记录并能复查”，不是泛化的检测准确率。

Design Choice
07 / 34
Sideband means no stall

记录满了怎么办

不采用

停住处理器等 trace

这样会改变被观察程序的执行节奏，也会让安全分析结果很难解释。

当前采用

丢记录并计数

当带宽不足时，trace 侧记录 DROP；汇报时只在捕获窗口内解释已记录且未丢失的结果。

Pointer / Source Boundary
30 / 34
Two careful boundaries

两个最容易被问到的边界

Pointer

硬件只做有界前缀

完整字符串语义仍主要靠受信 QEMU/strace companion 对齐，不能说硬件已经导出完整用户指针内容。

Source line

板上 trace 不是 DWARF 行号 trace
