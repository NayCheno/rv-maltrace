## Scope

This run corrects the Phase 5 trace-enabled FPGA integration after Phase 6
showed that the board trace path was bypassing the board-minimal event policy.

The corrective RTL change adds per-event enable inputs to
`rtl/trace/cva6_rvfi_trace_adapter.sv` and wires the Genesys2 FPGA trace path
through `trace_board_minimal_ctrl` inside
`rtl/cva6/corev_apu/fpga/src/ariane_xilinx.sv`, with matching simulation and
testbench updates.

## Build Sequence

- `uv run rvmt sim:trace-unit` passed after the adapter gating change.
- `uv run rvmt sim:cva6-smoke` passed after the CVA6 testbench wiring change.
- The first corrective `uv run rvmt bitstream:build-trace` attempt failed in
  synthesis because `trace_board_minimal_ctrl.sv` was not present in the FPGA
  generated source list; see `command_prefilelist_fail.log`.
- A second attempt still failed because `corev_apu/fpga/scripts/add_sources.tcl`
  is regenerated by `rtl/cva6/Makefile`; hand-editing the generated Tcl was not
  persistent. The durable fix was to add
  `$(RV_MALTRACE_ROOT)/rtl/trace/trace_board_minimal_ctrl.sv` to
  `rvmt_fpga_src` in `rtl/cva6/Makefile`.
- The next `uv run rvmt bitstream:build-trace` completed implementation and
  bitstream generation, but the routed design still had overall
  `WNS=-0.055ns`; see `command.log`.
- A route-only recovery from `ariane_xilinx_physopt.dcp` using
  `recovery_route_explore.tcl` reran `route_design -directive Explore`,
  regenerated routed reports and artifacts, and closed timing with
  `RVMT_RECOVERY_WNS=0.079`; see `recovery_explore.log`.
